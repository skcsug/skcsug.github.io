# 2026 OIBC Challenge 회고

> 태양광 발전량 예측 및 집합자원 정산금 최대화 경진대회 (2026.10 \~ 2026.11.13)
>
> 5인 팀 · 팀장 정현찬 · 최종 결과 **385팀 중 78위**
>
> 대회 기간의 시도와 실패를 정리한 문서다. 수치는 팀 저장소의 `submissions/log.md`와 `docs/experiments/` 기록에서 옮겼으며, 대회 데이터 원본은 포함하지 않는다.

## 1. 요약

전국 253개 태양광 발전소의 다음 날 시간별 발전량을 예측하고 이를 두 집합자원(G1·G2)으로 묶어 제출하는 대회였다. 트리 모델과 신경망의 앙상블에 외부 기상 예보(GFS·GEFS·ECMWF·CAMS·LDAPS)를 단계적으로 추가하여, 정산금을 첫 제출 대비 **+2,394만 원**(6,444,957,097 → 6,468,895,230원, 11/12 기준) 개선했다. 1위(6,481,211,774원)와의 차이는 약 1,200만 원이었고, 최종 순위는 385팀 중 78위다.

## 2. 문제 정의

| 항목 | 내용 |
| --- | --- |
| 입력 | 기상 예보 A·B(전날 17시까지 발행분), 발전소 정보(용량·위치·관측 지점), 과거 발전량, SMP |
| 출력 | 평가 구간(2025-06 \~ 2026-05, 1년)의 시간별 G1·G2 발전량 예측과 발전소별 G1/G2 배정 |
| 평가 | 정산금 = Σ SMP × 실제 발전량 − 페널티, 페널티 = 0.1 × Σ SMP × k × (\|G1 오차\| + \|G2 오차\|) |
| 제약 | 그룹별 설비용량 20,000 kW 이상, 첫 제출의 그룹 구성을 끝까지 유지, 하루 3회·총 20회 제출 |
| 외부 데이터 | 상업적 이용이 가능하고 동일 주소에서 누구나 다시 받을 수 있는 공개 자료로 한정(10/28 공지) |

**초기 분석 결과 (10/29)**

- 페널티의 **82%가 10\~15시**(가중치 k = 3 구간)에 발생한다. 따라서 주간 정확도가 성능을 결정한다.
- 오차는 **흐림 예보**에서 가장 크다. 운량 80\~100% 구간이 가중 오차의 41.8%를 차지한다.
- 그 밖에 겨울철 과대 예측(적설로 가려진 패널), 7월 과소 예측(장마 예보의 비관적 편향), 특정 발전소의 상시 과대 예측이 확인되었다.

## 3. 최종 모델 구조

```
                ┌─ 10t: 튜닝한 4종 앙상블 (LightGBM·XGBoost·CatBoost·MLP) + 2단계 보정
제출 =  0.1~0.2 ┤
                ├─ F 계열 0.6~0.7: 1단계 피처 묶음만 다른 세 모델의 평균 (rainhist / gfsgrid / gfsmoreday)
                │     각 모델 = LightGBM 0.3 + CatBoost 0.2 + XGBoost 0.3 + MLP 0.2, 2단계 보정
                │     피처: 대회 예보 가공 + GFS·GEFS·ECMWF + GFS 0.25° 1시간 일사 + CAMS(전 기간)
                │           + 겨울 가중(Fw) + 구름 유형·경사면 일사(Fwcp)
                ├─ n4 0.2: 신경망(MLP) 4개 평균
                └─ + AnEn 보정분: 과거 유사 예보일 20개의 실적 기반 보정
그룹 구성: balanced (용량 지그재그 배정, 첫 제출부터 고정)
```

- **2단계 보정**: 1단계 예측의 전국 합계 오차를 GFS 전국 요약값과 기온 변화로 다시 학습하여 보정한다. 리더보드에서 페널티 약 −2.8%를 확인했다.
- **채택 기준**: 모든 채택 기준을 결과 확인 전에 기록하고, 검증 2023·2024 **두 해 모두** 개선될 때만 채택했다.

## 8. 효과적이었던 운영 방식

- **사전 등록(pre-registration)**: 모든 채택 기준을 결과 확인 전에 문서로 작성하고 커밋했다. 검증을 반복하며 우연히 좋은 설정을 고르는 것을 방지했다.
- **두 해 동시 개선 기준**: 검증 2023·2024가 **모두** 개선될 때만 채택했다. 한 해만 개선된 변경은 리더보드에서 효과가 사라지는 경우가 많았다.
- **검증 → 리더보드 환산 추적**: 제출마다 검증 1%가 정산금 몇 원에 해당하는지 기록했다(0.2\~2.5배 변동, 평균 1% ≈ 117만\~216만 원). 기대값과 실제값을 비교하여 이상 제출(radmix)을 즉시 식별했다.
- **대조 제출**: 첫 두 제출을 보정 유무만 다르게 하여, 보정 효과를 리더보드에서 직접 확인했다.
- **재현성 관리**: 제출마다 커밋, 실행 명령, 환경 변수, 파일 해시를 `submissions/log.md`에 기록하고, 다른 PC·VM에서 동일한 정산금이 원 단위까지 재현되는지 확인했다.
- **협업 구조**: 작업 1건 = 브랜치 1개 = PR 1건 원칙을 적용하고, 작업별 `docs/tasks/` 문서(담당·규칙·진행 상황·인계 요약)를 운영했다. 4명이 노트북·데스크톱·VM 2대에서 병렬로 실험했다.

## 9. 개선이 필요한 점

- **그룹 구성 고정 규칙**: 첫 제출의 그룹 구성을 끝까지 유지해야 해서, 모델이 개선된 뒤에는 구성을 다시 선택할 수 없었다. 첫 제출 전에 구성 실험을 더 넓게 수행했어야 했다.
- **시계열 신경망 미검증**: 시계열 신경망을 주력 계열 위에서 판정하지 못했다. 파이프라인이 둘로 나뉘어 결과 비교가 어려웠다.
- **파이프라인 간 설정 불일치**: radmix는 보정을 끈 상태로 검증·제출되어 리더보드에서 크게 하락했다. 팀 전체가 동일한 판정 기준(보정 적용)을 공유했어야 했다.
- **전제 오류 1회**: 평가 구간을 겨울로 오인하여 기준을 잠시 겨울 월로 설정했다가, 결과 확인 전에 1년 전체로 정정했다. 판정 직전에 대회 규칙 문서를 재확인할 필요가 있다.
- **마지막 날 일정 압박**: 새 피처(Fwcp) 학습에 8시간이 걸려 마감 직전에야 제출 파일이 생성되었다. 16코어 VM으로 이관하여 해결했으나, 대규모 학습은 하루 앞서 시작했어야 했다.

## 10. 인프라·운영 이슈

| 문제 | 해결 |
| --- | --- |
| macOS에서 신경망(torch)과 LightGBM의 OpenMP 충돌로 프로세스 정지(4스레드에서도 발생) | macOS에서는 `OIBC_NN_THREADS=1` 설정, 신경망 학습은 Windows 데스크톱에서 수행 |
| 16GB 메모리 노트북에서 모델 2개 동시 실행 시 스왑 급증 | 한 번에 하나씩 실행 |
| 정렬 동점 처리 순서가 numpy 버전·CPU마다 달라 PC별로 구성과 점수가 상이 | `argsort(kind="stable")`로 고정 |
| 기상청 API허브 동시 요청 80건으로 IP 차단 | 동시 요청 10건 이하로 제한 |
| CAMS 표를 폴더 내 "가장 큰 파일"로 읽어, 학습 중 표를 교체하면 검증과 제출이 서로 다른 표로 학습됨 | 실행 흐름 종료 후에만 표를 교체하고 표의 md5를 기록 |
| LDAPS 생산이 2026-03-31에 종료 | 평가 구간 4\~5월은 LDAPS 미사용 모델로 대체 |
| 원격 데스크톱 SSH가 네트워크 단절 시 정지 | 5분 이상 유지된 연결을 끊는 감시 스크립트 적용 |
| 대회 데이터 외부 업로드 금지 | 팀 공유는 예측값(site_id, ts, pred)만 허용하고 실적 열은 제외, 비공개 저장소 사용 |

## 11. 기술 스택

- **언어·라이브러리**: Python, pandas, NumPy, LightGBM, XGBoost, CatBoost, PyTorch, scikit-learn
- **외부 데이터**: NOAA GFS·GEFS(0.25°·1° 격자, 층별 운량, 앙상블 분산), ECMWF IFS 공개 예보, Copernicus CAMS(일사·운량·에어로졸), 기상청 LDAPS(1.5 km)

- **AI 도구**: Claude Code를 실험 자동화, 판정 스크립트 작성, 원격 작업 감시, 문서화에 활용
